## Checked and found sound (reviewer)

- Path traversal: encoded dots, `%2f`, `%5c`, `//`, `%00` and `a/..%2f..` all return 403 or 404 (ran).
- Bind address: server and Chrome DevTools on 127.0.0.1 only, random ports (ran `lsof`).
- Fixture overlays: folder names are constants; `fixture.json` only feeds the missing, hang and delay lists, compared to the request target (read).
- Fake token: hard-coded dummy, fresh 0700 profile, removed per case; the owner's own browser profile is never touched (read).
- No real GitHub call on load; the stub is in place before publish is clicked (read).
- No injection paths: `spawn` with argument arrays and no shell; no `eval` in Node; page data comes back only through `JSON.parse` and base64; selectors are constants through `JSON.stringify` (read).
- Workflow: `permissions: contents: read`, `pull_request` (not `pull_request_target`), no secrets, actions pinned to a SHA (read).
- Exit codes: failures, a crash and missing Chrome all exit 1; only the empty filter passed falsely (finding 3).
- Checks are real: the version-less reads case uses a fixture without the key (grep).

## Not checked (reviewer)

A real run on GitHub's `ubuntu-latest` or with a fork pull request; where checkout v7 keeps the token; whether Chrome's Private Network Access rules would stop a public web page reaching the server; why a run on the owner's Mac hung for four hours (author's note: those were the author's own runs during an uncommitted harness change that hung; the orphaning is the flaw finding 1 describes); whether Chrome 155 checks the Origin header on DevTools connections.
